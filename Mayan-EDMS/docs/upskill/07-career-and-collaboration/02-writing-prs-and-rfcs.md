# Writing PRs and RFCs

## Good PR description shape

- What changed
- Why now
- How tested
- Risks
- Follow-ups

## Commit message guidance

- prefer narrow, behavior-focused commits
- mention app boundary when useful, such as `documents:` or `sources:`

## When to write an RFC

- cross-layer changes
- schema or migration strategy changes
- async workflow redesign
- permission model changes

## RFC template

### Problem
### Current behavior
### Proposal
### Alternatives considered
### Migration plan
### Test plan
### Rollback plan
### Open questions
